# gwemu RDP 模型基础验收

固定既有 gwemu 产物通过选项字节、内部 Flash 的真实 GDB 读写门禁、解除保护擦除、持久化和即时存档恢复验收。本批只增加测试/文档，未发现需要修改 native 的缺陷；不改变桌面入口或 legacy 默认，不执行实机或 manager unlock/reprotect CLI。

## 身份与观测边界

父起点779d092，沿用feat/gwemu-migration。native ae00b68951ab44b0dffb265e3f61340d735a68e5，build/gwemu-manager-ram/qemu-system-arm SHA25669750cd46454dab640d1e0d8c47c04b32ec703d09217a1730775887a99d8ad1a；manifest清洁且SHA匹配。manager固定7a82d653f23b5e3b5802eb4ce1e5076f94aa379b，旁manager dec4fdc9cb027f4c0df4e18984ce2ae29ce28df2，均未修改。

每场从临时合成镜像创建两份完整256KiB内部bank和1MiB外部Flash；不同重复字节图案可区分bank及保留/擦除。重开保留已有文件，不能重新种入原内容。所有GDB连接为自有native的Unix端点，使用真实m/M包、checksum和ACK。qtest socket只作寄存器写入及独立物理内存诊断，qtest读写不受同一保护过滤器限制，不能当作GDB门禁证据。

所有设备用普通TCG/-S暂停，只有guest用例显式cont；无icount/clock_step。RDP1下CPU仍可读Flash，测试明确分离CPU访问与debugger访问。此证明限于 canonical bank1 0x08000000..0x0803ffff、bank2 0x08100000..0x0813ffff，不证明任意boot alias、全部调试通道或实机抗调试安全机制。

## 实际结果

| 用例 | 验收结果 |
|---|---|
| keys/影子/提交 | 逆序、错key、byte写不能解锁；CUR只读；正确32bit KEY1/KEY2清除两个OPTLOCK；PRG仅暂存，OPTSTART后四个CUR/PRG字段一致；AA→55保留整份镜像 |
| RDP1的55与11 | 两bank首部、末部及跨上边界的GDB m/M均返回E14；失败写后整份bank不变；SRAM读写和开启XIP后的外Flash读取仍成功 |
| RDP1→0 | 两个完整256KiB bank变成FF，外Flash全部保留，SRAM sentinel保留；真实GDB恢复读/写能力 |
| guest CPU与GDB分离 | 55下GDB读取内部sentinel失败，Thumb程序仍从Flash读到正确值并写入SRAM；暂停后GDB仍拒绝 |
| RDP2 | CC后请求55或AA，CUR保留CC、OPTCHANGEERR置位、全部bank不擦除、GDB拒绝；退出重开后CC及拒绝保持 |
| 暖reset/退出重开 | 55及完整镜像保持，重开仍拒绝；解除保护后退出重开为AA、两个bank仍全部FF |
| 完整即时存档 | 保存55后解除保护擦除，再读档恢复两bank/外Flash、55 sidecar及即时GDB拒绝；读回AA状态恢复完整镜像/AA sidecar和可读能力 |

bank2别名一致性指成功提交后的字段和OPTLOCK状态；原模型的PRG影子独立，OPTSTART从bank1 PRG提交，本批没有扩展通用bank2提交语义。拒绝的RDP2降级可以保留尝试编程的PRG影子，不能据此称保护已下降。跨边界失败只证明受保护bank数据不变，不承诺包含其它未保护页面的任意多页写具有事务回滚。

首次运行误用了qtest accelerator，native日志明确不支持GDB；TCG guest用例当场通过。改为全部TCG后，两个外Flash访问用例仍E14，原因是独立OSPI XIP窗口初始EN=0/FMODE=00。显式设置EN=1/FMODE=11后读取成功，内部保护与擦除用例全部通过。两种失败均是夹具前提，不作为native缺陷RED，也没有为通过测试而修改模型。
