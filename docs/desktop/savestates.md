# 即时存档

“文件 → 即时存档”子菜单提供保存、读取和槽位 0–9。每次加载 ROM 默认选择槽位 0；菜单显示各槽位的保存时间。默认快捷键为 F5 保存、F8 读取、F6 上一槽、F7 下一槽，可在热键设置中修改，也可绑定手柄。

旧版设置首次升级时会补充这些默认热键，保留已有映射；已占用的按键不会被替换。之后删除或修改热键会正常保留。

保存范围包括 CPU、RAM、虚拟时间、已实现的外设状态、内部 flash 两个 bank 和外部 flash 原始内容。读取会覆盖**当前 session 的 flash 文件**，游戏内存档、固件配置和代码缓存都会回到即时存档时的状态。源 ROM 镜像不变。不比较当前 flash 的内容或哈希。

挂载任何 SD 镜像时，保存和读取都会显示“不支持”；SPI1 和软件 SPI 接线规则相同。支持外部 flash 最大 64 MiB，包括常见的 64 MiB 改装。容量更大的 flash 会显示容量提示。首次版本没有 SD 差分、自动存档或游戏自身的 savestate 接入。

底部 toast 显示保存/读取进度，操作结束后显示结果。成功与槽位切换提示保留 3 秒，不支持提示保留 5 秒；错误需要手动关闭。操作期间释放按键并暂停模拟器，完成后恢复原来的运行状态。退出会等待正在进行的操作。

## 文件与失败恢复

存档位于 `UserData/sessions/<ROM UUID>/states/`：

- `slot-0.json` 至 `slot-9.json`：引用当前槽位的版本文件夹，包含保存时间。
- `<版本 UUID>/state.bin`：完整 QEMU VMState 流及 GNW 格式/机型/flash 尺寸头部。
- `rollback-<UUID>.bin`：读档前临时恢复点；操作成功或回滚成功后删除。

保存先写一个新版本，完成并同步文件后原子更新槽位引用，然后清理旧版本。失败不会替换原槽位。读取失败会恢复读档前的运行状态及 flash；如果恢复点也无法读取，保持暂停，并保留恢复点供排查。重新加载 ROM 可重新启动模拟器。

断电或强制结束进程可能留下未引用的版本目录。即时存档格式依赖当前 QEMU 与外设模型版本，暂不保证跨版本兼容；使用同一 session、同一构建读取。挂载宿主实时 RTC 时，时钟仍遵循宿主时间；`clock=vm` 的 RTC 随虚拟时间恢复。

## 实现和验证

QMP `qom-set /machine save-state` / `load-state` 接收绝对文件路径，调用前必须暂停。`qom-get /machine savestate-support` 返回空字符串表示支持，`sd` 或 `flash-size` 表示拒绝原因。QEMU 层加载失败后保持暂停；桌面层负责临时恢复点和回滚。

内部 flash 通过可迁移 RAMBlock 保存；外部 flash 保存原始数据，解密 XIP 视图在加载完成后重建并使旧翻译代码失效。外设定时器、FIFO、未完成的 flash 编程、HASH 输入和 JPEG 解析缓冲区均随状态保存。宿主音量、显示连接、文件路径不随存档回退；读档时清空音频输出队列、同步显示尺寸，并重置实时节奏计时器。

已验证原厂 Mario/Zelda 同进程重复读档及重启后的恢复、64 MiB Retro-Go 恢复、flash 实际编程回退、未完成 OSPI 写入/HASH、画面尺寸切换、损坏文件回滚、SD 两种接线拒绝、超过容量拒绝，以及桌面真实菜单/快捷键/toast。未逐一验证所有移植游戏；它们可使用相同完整机器状态机制，但需要逐游戏运行验证。

本机一次测量（Apple Silicon，暂停中的 QEMU，原厂启动 1.5 秒；临时 session）：

| 镜像 | 状态文件 | QEMU 保存 | QEMU 读取含 flash 写回 |
| --- | ---: | ---: | ---: |
| Mario 1 MiB flash | 2,338,348 字节 | 2 ms | 12 ms |
| Zelda 4 MiB flash | 5,564,893 字节 | 3 ms | 20 ms |
| 64 MiB flash 固件 | 68,601,320 字节 | 28 ms | 33 ms |

这是本机单次测量，桌面读档还会先保存恢复点；文件系统、flash 加密范围和设备状态会影响时间。
