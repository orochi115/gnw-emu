# 机身显示与按键反馈

已接入 Mario/Zelda 机身、点击按键、键盘同步反馈及可持久化的边框开关。素材使用可复现的离线工具加工，运行应用不依赖 Python。

## 素材与外观

使用用户指定的两张官方正面图片：红色 Mario 与绿色 Zelda，按已加载配置的机型选择，空闲窗口继续使用简洁布局。原图保留材质、标签和文字，移除完整 LCD 内部画面，外侧保持原有透明度。素材尺寸、来源哈希、屏幕位置与按键几何由 `desktop/src/renderer/assets/chassis/<model>/skin.json` 管理，加工说明见该目录的 README。

照片底图加独立按键叠层兼顾原有质感和组合键。纯 CSS 按钮容易与原图风格脱节；整张状态图片会造成组合数量增长。叠层仅覆盖按钮表面，悬停略提亮，按下变暗并增加轻微内缘反馈。十字键按方向显示，中央支点不动。照片上没有的按钮不额外补画。

## 边框开关与布局

View/视图菜单提供“显示机身边框”勾选项，稳定 ID 为 `view.chassis`。默认开启，应用设置 `showChassis` 保存选择，重启应用后保留；它属于显示偏好，不写入 ROM 配置、不进入 QEMU。异步写入成功才更新应用偏好，失败保留旧偏好并恢复原生勾选。连续切换串行执行，避免覆盖其他设置。

关闭边框恢复纯游戏画面。切换不重新加载 ROM、不改变会话与存档、不重启 QEMU，Canvas 与 MessagePort 保持挂载。切换前及偏好写入完成后均释放机身来源，覆盖磁盘等待期间到达的新按下；保留其他键盘来源。松开事件即使在控件隐藏后也能经过校验处理。

整台机身在可用区域按比例居中，保留留白。Canvas、底图和按键使用同一坐标系，以素材元数据定位。LCD 保持原有画面比例，使用最近邻显示，禁止平滑滤波、裁剪和拉伸。机身模式允许小数缩放以对齐照片窗口；纯画面模式保持整数优先策略。缩放窗口时同步调整显示尺寸与坐标映射，Canvas 内部保持源像素尺寸，HiDPI 由 Chromium 合成处理；不为机身增加帧传输或 QEMU 操作。

原生系统窗口边框保留；“机身边框”仅指内部图片。系统浅色/深色主题作用于周围界面，不给照片施加主题滤镜。

## 输入边界

renderer 负责真实按键控件、指针捕获和图片叠层；main 的输入服务负责来源聚合、映射和有序 QMP 提交。视觉状态从聚合后的逻辑按键 mask 推送，不能仅依赖 CSS `:active`，键盘与鼠标显示一致。

每个指针使用独立来源 ID；释放 A 不影响仍按住的 B。同一按钮的键盘来源仍按下时，松开鼠标不释放该逻辑按钮。指针捕获与窗口事件兜底处理移出后的松开；取消、捕获丢失、失焦、弹窗、停止、换游戏及关闭边框均释放对应来源。失焦清空全部输入。主进程用 `resetGeneration` 明确发布重置，普通聚合快照只更新显示；不能因为较早快照未包含新按下的 bit 就清理本地来源。指针命令与清理携带 `runtimeSessionId`，旧运行的迟到事件不能操作新游戏。转换串行提交，不吞掉短按。

控件有真实 button 语义、本地化名称、焦点轮廓和稳定 ID `chassis.button.<logical-id>`。照片上没有的 POWER 保留键盘入口。改键与游戏重启可作为后续独立任务。

机身模式下 Tab/Shift+Tab 从画面进入并遍历控件，Space/Enter 按下聚焦按钮，改变焦点即释放该来源。未聚焦按键时 Return 仍为 START。Q 在两种模式下均为 SELECT；纯画面模式保留 Tab=SELECT。应用仍处理焦点变化后的游戏键松开，避免从画面按住 Return 后移动焦点留下 START。

## 自动化、日志与验收

自动化沿用 UI Driver/JSON-RPC，操作真实的 `view.chassis` 菜单与控件。`ui.pointer` 长按/松开发送 Electron 鼠标事件，结合 `ui.key` 测试混合来源。`ui.inspect` 返回 `chassis.visible/model/input`、按钮 `pressed` 和菜单 `checked/type`。`app.getDiagnostics.input.desiredMask/appliedMask` 区分期望状态与 QMP 已确认状态，原 `buttons` 保留为 desiredMask 别名；应等待确认后断言。

Pino 的 view 模块 `chassis.visibility` 记录 info；input 的 `button/key/mask` 记录来源转换和 QMP 确认（debug），`submit.failure` 记录提交失败（error）。相关事件带运行会话 ID，不记录 pointermove 和逐帧像素。

验证使用实际 Electron/QEMU、RPC 与截图，覆盖两个机型的 LCD 对齐、持久化/失败、切换、混合输入、多来源同键、真实双指触摸取消、Tab/Space 焦点、失焦/模态释放、迟到会话事件、浅深主题、380px/1000px 窗口及 Retina 显示、帧流持续递增。单元测试补充有序 QMP 确认、等待写入期间的新按下、连续切换与失败恢复。具体结果与平台范围见 [验证记录](validation.md)。
