# 机身显示与按键反馈

已接入 Mario/Zelda 机身、点击按键、键盘同步反馈及可持久化的边框开关。素材使用可复现的离线工具加工，运行应用不依赖 Python。

## 素材与外观

使用用户指定的两张官方正面图片：红色 Mario 与绿色 Zelda，按已加载配置的机型选择，空闲窗口继续使用简洁布局。原图保留材质、标签和文字，移除完整 LCD 内部画面，外侧保持原有透明度。素材尺寸、来源哈希、屏幕位置与按键几何由 `desktop/src/renderer/assets/chassis/<model>/skin.json` 管理，加工说明见该目录的 README。

照片底图加独立按键叠层兼顾原有质感和组合键。纯 CSS 按钮容易与原图风格脱节；整张状态图片会造成组合数量增长。叠层仅覆盖按钮表面，悬停略提亮，普通按钮按下变暗并增加内缘反馈；十字键增加暖金色表面与明亮内缘，在紧凑窗口中也清楚可见。十字键按方向显示，中央支点不动。照片上没有的按钮不额外补画。

## 边框开关与布局

View/视图菜单提供“显示机身边框”勾选项，稳定 ID 为 `view.chassis`。默认开启，应用设置 `showChassis` 保存选择，重启应用后保留；它属于显示偏好，不写入 ROM 配置、不进入 QEMU。异步写入成功才更新应用偏好，失败保留旧偏好并恢复原生勾选。连续切换串行执行，避免覆盖其他设置。

关闭边框恢复纯游戏画面。切换不重新加载 ROM、不改变会话与存档、不重启 QEMU，Canvas 与 MessagePort 保持挂载。切换前及偏好写入完成后均释放机身来源，覆盖磁盘等待期间到达的新按下；保留其他键盘来源。松开事件即使在控件隐藏后也能经过校验处理。

整台机身在可用区域按比例居中，不再预留四周 16px 留白或外侧阴影。加载机型、开关边框时按机身比例调整窗口内容高度，减少外圈空白；用户主动调整为其他窗口比例或最大化时仍使用等比容纳。Canvas、底图和按键使用同一坐标系，以素材元数据定位。两种机型的 QEMU 输出均为 320×240、4:3，LCD 保持这一原始画面比例，使用最近邻显示，禁止平滑滤波、裁剪和拉伸。机身模式允许小数缩放以对齐照片窗口；纯画面模式保持整数优先策略。缩放窗口时同步调整显示尺寸与坐标映射，Canvas 内部保持源像素尺寸，HiDPI 由 Chromium 合成处理；不为机身增加帧传输或 QEMU 操作。

窗口采用同一无系统边框 BrowserWindow；普通模式提供 32px 自绘标题栏，可拖动、菜单、最小化、最大化/还原及关闭。macOS 系统菜单保留；标题栏菜单按钮也可访问原生 Menu，Windows/Linux 隐藏系统菜单行以保持一致。关闭沿用现有保存/退出流程。“机身边框”开关只控制图片。系统浅色/深色主题作用于周围界面，不给照片施加主题滤镜。

## 输入边界

renderer 负责真实按键控件、指针捕获和图片叠层；main 的输入服务负责来源聚合、映射和有序 QMP 提交。视觉状态从聚合后的逻辑按键 mask 推送，不能仅依赖 CSS `:active`，键盘与鼠标显示一致。

每个指针使用独立来源 ID；释放 A 不影响仍按住的 B。同一按钮的键盘来源仍按下时，松开鼠标不释放该逻辑按钮。指针捕获与窗口事件兜底处理移出后的松开；取消、捕获丢失、失焦、弹窗、停止、换游戏及关闭边框均释放对应来源。失焦清空全部输入。主进程用 `resetGeneration` 明确发布重置，普通聚合快照只更新显示；不能因为较早快照未包含新按下的 bit 就清理本地来源。指针命令与清理携带 `runtimeSessionId`，旧运行的迟到事件不能操作新游戏。转换串行提交，不吞掉短按。

控件有真实 button 语义、本地化名称、焦点轮廓和稳定 ID `chassis.button.<logical-id>`。照片上没有的 POWER 保留键盘入口。改键与游戏重启可作为后续独立任务。

游戏运行时，两种显示模式均使用 Tab=SELECT、Return/Enter=START，聚焦机身按钮也不改变含义；Q 保留为 SELECT 别名。游戏中不使用 Tab 遍历机身或 Enter 激活按钮。制作 ROM 对话框保留原生 Tab/Enter 表单行为；明确聚焦的机身按钮仍可用 Space 操作，供辅助技术使用。

## 桌面时钟模式

从“视图 → 桌面时钟模式”（`view.clock`）进入。需已有运行中的游戏，未加载时菜单禁用；此状态只在本次应用运行中有效，不写入设置。进入时释放按键、记录普通窗口位置/大小、最大化状态与原有置顶状态，退出全屏/最大化后按当前屏幕像素密度恢复 LCD 像素 1:1 并置顶，隐藏标题栏。有无机身均以 QEMU 的 320×240 为基准：2× Retina 上无机身占 160×120 逻辑像素，Zelda 机身约 366×219、Mario 约 364×218 逻辑像素。整台机身按 LCD 尺寸同步缩放。切换机身也恢复 1:1。

窗口边缘可继续拖动缩小，最小约束从 320×180 降为 80×48 逻辑像素（极高像素密度时还会适应默认尺寸）；手动缩放保持比例并使用最近邻显示。小于 1:1 会缩小采样，无法同时保留所有源像素。通过“视图 → 恢复像素 1:1”（`view.actualSize`）或右键菜单恢复默认尺寸。1:1 状态明确记录为 `pixelPerfect`；手动改尺寸退出该状态。

这里的像素 1:1 是一个 QEMU 像素对应一个 Chromium 输出像素，并非一个 QEMU 像素对应一个 CSS 逻辑像素。应用保持原始 Canvas 像素尺寸，经 1/devicePixelRatio 的变换及输出像素网格对齐显示，避免分数 CSS 布局量化；机身透明孔也按相同边界裁切，防止照片 alpha 滤波混入 LCD 边缘。macOS 的非原生缩放显示模式可能再缩放整张桌面，因此截图验证应用输出不能证明面板子像素完全一致。

跨屏幕或修改显示像素密度时，当前 1:1 会按新密度调整窗口；手动缩小的窗口保留逻辑尺寸。1:1 尺寸调整保留窗口中心，避免不同 DPI 屏幕交界处因面积归属变化而来回切换。主进程监听显示密度与窗口移动，renderer 监听 resolution 媒体查询，即使逻辑窗口大小不变也重新布局。正常退出模式仍恢复之前窗口。

模式只改变窗口：QEMU 进程、运行 UUID、Canvas、MessagePort 都保留，不暂停、不注入 TIME、不改变声音。按 TIME 按钮或 T 键进入当前固件的时钟画面；画面由固件决定，非官方固件不保证提供时钟。机身空白区域/纯画面可拖动，真实机身按钮仍能点击。悬停窗口会显示返回普通窗口和关闭按钮；右键菜单也提供返回与退出。恢复原位置/大小、最大化与之前的置顶状态；从全屏进入的窗口恢复普通窗口几何。ROM 加载/制作和原生 Zoom 在紧凑模式禁用，先返回普通窗口。

失焦立即清空输入，主进程也会拒绝失焦时的新键盘/机身按下，有效松开仍可清理。没有全局键盘监听，因此其他应用中的按键不会送给游戏。恢复焦点后需重新按键。全屏动画完成后会重新核验运行状态，避免运行已停止却进入紧凑模式；运行出错或结束会恢复普通窗口显示错误。关闭仍先正常退出 QEMU 并保存。


## 自动化、日志与验收

自动化沿用 UI Driver/JSON-RPC，操作真实的 `view.chassis` 菜单与控件。`ui.pointer` 长按/松开发送 Electron 鼠标事件，结合 `ui.key` 测试混合来源。`ui.inspect` 返回 `chassis.visible/model/input`、按钮 `pressed` 和菜单 `checked/type`。`app.getDiagnostics.input.desiredMask/appliedMask` 区分期望状态与 QMP 已确认状态，原 `buttons` 保留为 desiredMask 别名；应等待确认后断言。

Pino 的 view 模块 `chassis.visibility` 记录 info；input 的 `button/key/mask` 记录来源转换和 QMP 确认（debug），`submit.failure` 记录提交失败（error）。相关事件带运行会话 ID，不记录 pointermove 和逐帧像素。

验证使用实际 Electron/QEMU、RPC 与截图，覆盖两个机型的 LCD 对齐、持久化/失败、切换、混合输入、多来源同键、真实双指触摸取消、Tab/Enter 游戏映射、Space 焦点、失焦/模态释放、迟到会话事件、浅深主题、380px/1000px 窗口及 Retina 显示、帧流持续递增。单元测试补充有序 QMP 确认、等待写入期间的新按下、连续切换与失败恢复。具体结果与平台范围见 [验证记录](validation.md)。
