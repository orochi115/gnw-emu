# 已授权设备缺口修复

用户在原厂启动修复和设备审查后要求“请帮我修复”，范围是上一轮确认的冷启动失败、NOR 编程约束、DAC/背光、PWR 标志、TIM 位宽和 LTDC Layer 1 格式。已有迁移/供电设计继续有效，父仓库仅本地提交，native fork 可公开发布，源 ROM、现有 UserData、`.superpowers` 和真机不改动。

选择继续补齐 gwemu：保留其现有 DMA、时钟、编解码、管理会话、USB/电池与存档能力，移入旧模型中正确且有证据的设备语义。双内核并行会重复维护产品契约；回退旧内核会丢失已完成的迁移能力。旧机器及历史产物保留为对照，不重新接入产品。

先追踪真实 Retro-Go 冷启动的数据/控制流，定位造成 WFI 停留的具体设备、复位语义或验收输入错误；不靠修改 RTC、强制跳转 Bank 2、绕过设置校验或接受旧截图解决。每个原生设备缺口先以独立失败用例验证，再依据 MCU/NOR 寄存器契约修复。旧代码仅作参考，已知错误（如 CSSF 清 SBF）不能照搬。

NOR 补写使能、单向编程和页内回绕；DAC 补触发、双通道、通道使能及保持寄存器的别名语义；背光由 PA4/DAC 数值作用于实际 scanout，包括熄屏。PWR 补 W1C/自清零和必要的具体唤醒行为，保留既有供电来源协调。TIM2/5 为 32 位，其余相应实例为 16 位。LTDC Layer 1 复用当前通用像素解码/混合能力覆盖合法 PFCR 格式，保留 RGB565/L8 快路径和 Layer 2。

验证原问题及直接回归：原厂 TIME/重开、Retro-Go 冷启动与供电恢复、NOR 实际持久化、DAC/背光截图、PWR/TIM MMIO、Layer 1 格式与现有显示/存档测试。固件与 SD 均挂载副本，成功/失败后复核源哈希。完成后固定源码/二进制来源、更新开发默认产物，必要的软件检查通过后发布 native、父仅本地提交。沿用用户有限审查规则，不开启重复全量审查循环。
