# 自定义按键、手柄与热键设计

日期：2026-11-10。本文记录已经讨论确认的产品设计，并给出进入实现规划所需的技术默认规则。尚未授权开始功能实现。

## 目标与范围

为 Electron 桌面端提供键盘、手柄自定义映射、按住连发及可配置热键。Mario / Zelda 共用应用级配置。普通按键与热键采用同一输入图标系统，并跨页检测会同时触发多个动作的冲突；冲突仅提示，不阻止保存或执行。

本轮包括现有功能的热键配置，不开发即时存档、即时读档等未来动作，不引入全局系统键盘监听、不在失焦时控制游戏，也不新增多套命名 profile 或按 ROM 分别配置。

参考原型：`.superpowers/brainstorm/65706-1794295776/controls-layout-v5.html`。原型不接入实际设备或 QEMU，也不作为可维护的应用实现直接复制。热键页采用本文中的表格与组合图标规则。

## 控制配置窗口

提供“按键映射 / 热键配置”两个页面与统一的保存、取消入口。未加载 ROM 时也能编辑；已加载时默认展示对应机型，并可切换参考图，切换图不改变绑定。

全部修改先更新页面草稿。详情框的“完成”只关闭详情；退出详情不撤销已录入内容。整页“保存”在持久化成功后应用新配置并关闭窗口；“取消”丢弃本轮映射、设备参与选择和默认连发频率的修改。关闭配置窗口等同取消，避免无意保存。保存失败保留草稿和旧有效配置，并显示简短错误。输入隔离必须持续到窗口真正关闭。

恢复默认只修改草稿，直到整页保存才成为有效配置。中英文文案沿用应用本地化系统。

### 按键映射页

完整机身原图位于中央，四周为固定大小的配置泡泡，每个逻辑键一条独立引线。引线不能重合或交叉，采用浅色宽描边与深色细线；悬停或聚焦时高亮泡泡、引线及目标位置。

使用原始完整图片，保留屏幕内容，不使用为游戏画面挖空的边框图片：

- Mario：`retro-go-assets/images/official/eu/NSwitch_GameWatch_Legendary_Hardware.png`。
- Zelda：`retro-go-assets/images/official/eu/NSwitch_GameWatch_TLOZ_Lifestyle_04_image950w.png`。

逻辑键为上、下、左、右、A、B、GAME、TIME、PAUSE/SET、POWER、START、SELECT。全部属于普通机身输入，不能因为原厂用途而放到热键页。POWER 标注侧面按键。Mario 也可编辑 START / SELECT，但这两个泡泡不画引线，并用简短扩展按键标记说明图片上没有实体按钮。

每个泡泡展示混合排列的键盘和手柄图标。键盘采用键帽轮廓，手柄采用控制器轮廓，中间为短按键名，完整设备和输入名称在悬停 / 聚焦提示中显示。溢出横向滚动，可用左右箭头翻页；加号固定在最右侧，不参与滚动。原型每次展示两个完整图标，正式尺寸按可读性细化，不允许半个图标遮蔽删除或连发标记。

一个逻辑键允许多个输入；同一输入也允许映射到多个不同逻辑键，按冲突规则提示。方向支持手柄十字键和摇杆同时映射，不要求用户在两者中选择。提供添加整组方向的便捷操作，详情可按方向逐项更改。此页不支持组合键。

普通与连发绑定共用一行。连发使用金色与闪电角标，并在泡泡标题提示存在隐藏的连发绑定，不能只靠颜色区别。图标右上角删除按钮在悬停 / 聚焦时可见；详情和右键菜单同样提供删除入口。

### 单条映射详情与录入

点击一个图标只编辑它对应的一条映射；加号创建一条新映射。详情显示输入图标、设备 / 按键名、目标逻辑键和简短录入状态，不展示候选键列表。

打开详情进入录入状态。普通页采集一个实际输入后立即更新详情和页面草稿，并停止本次录入。后续按键不得继续替换；点击“重新录入”才重新监听。未完成录入的空条目不保存。完成、Esc 或关闭详情保留已形成的草稿修改。

连发采用分段单选栏：普通、默认频率、6 / 10 / 15 次每秒。默认频率可在页面顶部以同样的分段控件设置，初始 10 次每秒。选中普通关闭连发，选择频率启用按住连发；默认选项动态继承全局频率，显式频率不受全局修改影响。详情里的删除只移除这一条映射。

右键菜单为编辑、连发二级菜单、删除。连发子菜单包含普通、默认频率和指定频率，当前项有选中标记，不使用下拉框或另一个启用连发开关。右键操作是快捷入口，所有必要操作也能从点击详情完成。

## 热键页

使用竖直滚动表格，每行是一个动作名称和映射输入组。操作列保持可识别；绑定列支持多个绑定组横向滚动，固定加号。以后新增动作只增加行，不改变布局。

单键复用普通页图标。组合键使用共同外框中的多个输入图标，以加号连接，修饰键可采用较窄图标。组内图标不会被误当成互相独立的映射。整组编辑、删除、提示冲突。

每条热键单独配置修饰键，没有统一的热键专用键。键盘组合由一个主键和 Ctrl / Shift / Alt / Meta 的集合组成，详情支持直接录入组合，也提供修饰键切换控件。手柄组合由同一手柄的按钮集合组成；不支持跨设备组合。热键不支持连发，手柄轴用于普通方向输入，不作为本轮热键组合主键。

热键组合录入在参与组合的所有输入松开后结束，采集期间更新预览，完成后更新草稿并停止监听。不按固定短超时猜测组合，也不在第一个手柄按钮按下时立即结束。原生 Tab / Esc 导航和它们的录入须通过明确的录入状态处理，不能导致用户无法退出；正式 UI 的录入按钮支持鼠标、键盘和辅助技术。

### 初始动作范围（现有功能的技术默认清单）

动作注册表采用稳定 ID，与原生菜单复用执行函数和可用状态。初始提供：载入 ROM、制作 ROM、显示 / 隐藏机身、进入 / 退出桌面时钟、静音切换、电量增加、电量减少、USB 供电切换。

保留现有默认 CmdOrCtrl+O / CmdOrCtrl+N 和电量 Minus / Equal、USB KeyC。其余新热键默认不绑定。当前不支持的动作不注册占位行，例如即时存档 / 读档；以后实现功能时再注册。

依赖运行会话的动作在无会话时不能执行，时钟等动作沿用现有可用状态。原生菜单加速键与自定义热键不可把同一动作执行两次。原生系统编辑菜单等固定操作在录入阶段须避让捕获，但不改造成本轮热键编辑功能。

自定义热键替换或删除载入 / 制作 ROM 的默认绑定后，原生菜单必须同步移除旧加速键，并显示当前可表达的主要键盘绑定；额外绑定仍由统一输入路由处理。菜单执行和输入派发必须只有一个权威执行入口，不能保留隐藏的默认 CmdOrCtrl+O / N。

## 匹配与冲突

键盘采用物理 `KeyboardEvent.code` 保存身份，显示平台适合的名称；不能用大小写字符区别键位。普通页匹配键位，不要求修饰键集合；因此 Shift+A 可同时触发普通页 KeyA 和热键 Shift+KeyA。

键盘热键按修饰键集合精确匹配。例如热键 A、Shift+A、Ctrl+Shift+A 各自只在对应组合下执行，彼此不标为冲突。热键按主键的新按下边沿触发，系统重复 keydown 不重复执行；仅改变修饰键不能重复触发仍按住的主键。

手柄热键在所需按钮都按下时触发一次，任一组成按钮释放后才可重新触发；无关按钮或方向不会阻止组合。较短组合与包含它的较长组合可能都执行，应检测并提示，不自动吞掉较短绑定。这是本轮技术默认规则。

冲突定义为同一可达输入状态 / 输入序列会使多个不同动作或输出映射生效。检测覆盖两页所有有效绑定，包括普通键与带修饰键热键、普通与连发、手柄单键与组合、组合包含关系。所有受影响的图标 / 绑定组都加特殊颜色和感叹号，不依赖颜色单独表达。

多个不同输入映射到同一个普通输出不冲突，例如键盘 X、手柄 A 各自触发机身 A。普通和连发使用同一个实际输入会互相影响，应提示冲突。同一目标下完全相同的绑定拒绝重复添加，提示编辑已有条目。

详情按动作名称与所在页面列出冲突对象，并说明触发条件。例如“Shift+A 同时触发：按键映射 → 机身 A”。允许保存并同时执行所有匹配动作，不采用优先级吞输入，不按警告颜色改变运行行为。

## 手柄与设备

技术首选 Electron renderer 的 Gamepad API，必须通过实际 USB / 蓝牙设备验证 macOS 当前打包环境中的识别和轮询，再决定是否需要额外适配。读取原始设备状态与路由游戏输入分离，配置期间仍可录入手柄但不能传给游戏。

运行时键盘与参与输入的手柄同时可用。绑定记录设备来源或可复用的设备类型匹配键，而非只记录按钮编号，也不能把容易变动的连接 index 当作持久身份。同类型重连恢复绑定，拔掉保留配置；明确区分运行时实例和持久匹配。

设备状态列表展示连接情况，并提供参与输入开关。系统将同一物理设备暴露为两个接口时，不以名称相同或同时按键武断自动合并。一次录入检测到多个候选设备来源时须选择来源，不能自动创建多条映射；用户可禁用重复来源。无法可靠区别的相同设备应清楚显示接口 / 实例以供选择，不承诺 API 无法提供的唯一物理身份。

能区分的接口使用 API 设备 ID、映射类型与按钮 / 轴结构形成持久匹配信息，并保存参与输入选择。同样指纹的多个实例无法可靠区分时，单实例参与选择仅对本次连接有效，并在设备状态里明确标记；重连恢复可区分的设备规则，不能把旧 index 的禁用状态错误套给另一只手柄。此限制不影响共享按键配置的持久化。

默认键盘保留现有全部映射。识别为标准映射的手柄技术默认提供十字键 + 左摇杆、底部按钮 → A、右侧按钮 → B、Start / Back → START / SELECT。GAME / TIME / PAUSE / POWER 默认不占用手柄键。非标准映射设备由用户录入，不猜测按钮标签。摇杆方向使用可调死区与进入 / 退出阈值防抖，录入新方向要求先回中再明显偏转，避免启动时漂移自动录入。

摇杆死区放在设备状态的方向设置中，按可持久匹配的设备规则保存。默认死区 20%，进入阈值 25%、退出阈值 20%；死区允许 5%–60%、步长 5%，进入阈值自动为死区加 5 个百分点。展示一个死区控件即可，不要求用户同时理解两种阈值。轴值必须有限且归一化到 -1 至 1；非法样本不形成新的按下。

## 连发运行语义

频率单位是一秒完成几次按下 / 松开周期，采用等长按住和释放阶段；只在该绑定的物理输入保持按住时运行，不提供切换式永久连发。

每条绑定是独立输入来源，来源 ID 包含绑定和设备实例。普通按下与其他来源的连发取 OR；普通来源持续按住时，连发不能强行释放它。多个来源绑定同一逻辑键也不能互相误释放。

连发由可停止的统一调度器管理，输出变化走现有有序 QMP 提交，不通过 renderer 动画帧驱动，也不能让 QMP 积压产生无限延迟。设备断开、失焦、配置打开、停止 / 换游戏和退出均停止对应连发并释放输入；不自动恢复旧长按。

## 配置期间与生命周期输入隔离

配置窗口打开前，在主进程进入隔离状态，停止连发、释放已有输入并有序提交全释放。隔离期间的输入只能用于配置 UI，不得执行机身键、热键、设备快捷操作，也不能因原生菜单加速键意外启动操作。

隔离必须在主进程输入入口和运行时路由层生效，不能只依靠 renderer 的 preventDefault 或 DOM 弹窗检查。键盘、手柄、机身指针及迟到 IPC 均受约束。用配置代次与会话 ID 拒绝迟到按下，松开 / 清理仍可维护状态。已存在的有序 QMP 链须先完成释放屏障再允许录入；不要求暂停 QEMU，游戏可继续运行但保持中性输入。

配置关闭后，仍按住的键 / 手柄按钮 / 摇杆方向必须先释放或回中，再接受新的按下。按输入或设备独立处理，不能让一只漂移手柄永久阻塞所有设备。不回放配置期间的输入，不因新配置刚生效而立刻执行当前仍按住的键。

窗口失焦、应用退出、会话停止 / 切换、renderer 重载等清理路径沿用同样原则。保存失败不解除隔离。由固件处理的 START / SELECT 是否有作用取决于固件，不能伪造缺少实体键的模型行为。

## 实现边界与现有代码

现有固定键盘表位于 `desktop/src/core/input-controller.ts`；该类已经按来源聚合，并串行提交 QMP。保留来源与聚合语义，新增规范化输入、映射匹配、热键派发、冲突分析和连发模块，不把整个功能堆进一个文件。

`desktop/src/core/session-controller.ts` 中 Minus / Equal / C 的硬编码设备快捷操作需迁移到统一动作注册表，避免绕过可配置热键或隔离。`desktop/src/main/index.ts` 的 IPC、焦点及 modal 边界扩展为集中输入隔离。renderer 的固定 gameKeys 和修饰键过滤需改为统一路由，配置录入与运行输入明确分开。

配置属于应用 settings，不写入 ROM profile 或 session。建立带版本的控制配置子结构，使用现有 `settings-store.ts` 原子串行更新；旧 settings 缺字段时迁移到默认键盘映射，完整校验边界、动作 ID、输入身份和频率。稳定绑定 ID 支持删除、冲突指向和来源清理。配置更新失败不能丢失其他窗口、音频或最近 ROM 设置。

主进程负责保存、动作执行、隔离、来源聚合与连发；renderer 负责设备读取、图示、录入和草稿编辑，IPC 只传经过校验的输入数据和控制配置。设备读取中断必须释放实例来源，旧连接输入不能操作新会话。

## 验收与验证

实现计划应按以下边界分阶段：配置与规范化输入、运行路由 / 隔离 / 连发、普通页、热键页、自动化与打包验证。每阶段有独立验收，不开始时就重构无关代码。

必要单元验证包括旧设置迁移、键位与修饰键匹配、跨页冲突和手柄包含组合、多来源 OR、连发定时与停止、事务保存 / 取消、隔离代次与松开后恢复。

实际 Electron / QEMU 验证包括两机型图示、完整图片与独立引线、溢出翻页、详情录入后停止监听、分段栏与二级菜单、组合键松开后录入、冲突两侧提示及同时执行、键盘与手柄并用、断开 / 重连 / 失焦、配置录入不改变 QEMU mask 或设备属性、关闭时长按不会漏入游戏、保存失败不解除隔离和持续帧流。

优先在 macOS 当前开发 / 打包环境验证 USB 与蓝牙手柄，记录真实设备与虚拟输入测试的差异；不能以模拟 Gamepad API 测试代替真实硬件验证。扩展现有 UI Driver 的 inspect、菜单、图标、组合录入和诊断状态，使重要验收可重复执行。按改动运行 typecheck、必要单元测试、对应 E2E 和打包检查；不要为静态文案和颜色写镜像测试。
