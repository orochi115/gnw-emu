# gwemu 内核替换与 gnwmanager 工具链统一

日期：2026-11-12。状态：讨论确定的迁移方向，供后续分阶段制定实施计划。本次仅记录并提交文档，不执行代码迁移、仓库归档或远程发布。

## 目标与最终状态

保留 gnw-emu 的桌面产品和 `.gnw.json` 工作流，以 gwemu 替换现有 QEMU 机器实现，将完整备份与模拟设备管理集中到 gnwmanager。

最终只维护一套基于 gwemu 的模拟内核。迁移期间保留旧内核作为对照；验收通过后移除旧子模块和实现，并归档旧 QEMU fork。完整备份迁入 gnwmanager 且通过恢复验证后，移除 backup 依赖并归档其 fork。

当前 sylverb Flash-only 和 SD Retro-Go 都通过 gnwmanager 管理设备；这两种固件用途继续保留。旧分支的 OpenOCD 刷机路径退出选定工具链，不要求实现 OpenOCD 兼容服务。

## 架构与职责

```text
gnw-emu-ui ──进程生命周期、profile/session──→ gwemu/QEMU
     │                                          ↑
     └──本地当前会话入口──→ gnwmanager ──GDB─────┤
                              └──机器控制接口───┘
```

- **gwemu/QEMU**：CPU、STM32 外设、Flash/SD 和机器电源行为；开放 GDB 与必要的机器控制接口。
- **gnw-emu-ui**：加载 profile、创建隔离 session、启动/停止 QEMU、显示帧与处理交互、发布当前会话信息。
- **gnwmanager**：完整备份/校验/恢复、固件上传和刷写、文件系统管理、监视/截图与调试连接。
- **会话入口**：让客户端发现当前会话身份、连接端点、运行状态与控制能力。优先用本地 socket 作为发现入口；GDB 与 QMP 可保持独立端点，不必统一线协议。

UI 未加载 ROM 时不要求启动 QEMU。加载 ROM 时启动，换 ROM 时结束旧会话并建立新会话，关闭 UI 时停止进程。不先引入常驻 daemon；协议职责与进程管理分离，便于以后增加无 UI 启动方式。

`.gnw.json` 保持宿主入口，固件不解析它。将 profile/session 映射成 gwemu 的镜像与设备参数，不要求 gwemu 原生读取该 JSON，也不要求用户改用 gwemu 自带 UI 或 profile.toml。

## 阶段一：gwemu 内核替换

1. 引入 `slash-proc/gwemu` 子模块，固定经过验证的 commit，记录构建工具链与产物来源。
2. 建立可重复构建和同镜像对照运行；旧 QEMU 仅在迁移期保留。
3. 适配当前 UI 的机器参数、QMP/QOM 控制、帧传输、音频、输入、RTC、UID、Flash/SD 持久化与进程锁。
4. 保留基线 ROM 与 session 隔离，刷写和存档恢复只作用于 session。适配即时存档的 CPU/RAM/外设及完整 Flash 回滚语义，保持现有 SD 不支持和容量边界，除非后续另行扩展。
5. 根据验收发现补齐电池存在/断开、USB 电源、冷启动、软件 SPI 接线等机器模型缺口。使用 gwemu 的现有能力，避免把旧 STM32 模型整套复制过去。
6. 上游接口无法满足产品接入或模型需修改时，建立自己的 gwemu fork，集中维护小范围补丁并尽量贡献上游。

本地当前 QEMU 已编译 GDB 支持；迁移后的 gwemu 构建也须验证该能力，并配置运行时入口。无需把“开启 GDB”视为独立重编译功能项目。

### 验收与退出旧内核

- 同一组已记录哈希的内部/外部 Flash、bank2 和 SD 镜像覆盖 Mario/Zelda OFW、Flash-only Retro-Go、SD Retro-Go，并能运行 gnwmanager RAM 管理固件。
- 现有桌面功能通过对应回归检查：帧显示、音频/静音、键盘/手柄、热键、电源、RTC、换 ROM、关闭、session 持久化和即时存档。
- 明确验证现有 SD 接线方式、完整 Flash 回滚和 source ROM 不变。旧即时存档不能假定跨内核兼容；识别并拒绝不兼容状态，保留旧文件和 session 数据，记录兼容结果。
- 对现有功能的失败逐项修复并复验后，才将 gwemu 切为唯一内核。尚待阶段三完成的管理功能另列验收，不能宣称工具链已全通过。
- 给旧 QEMU fork 留下最终 tag、可复现构建说明和历史引用，再移除子模块、旧机器实现、专用补丁及构建依赖并归档远程 fork。

## 阶段二：完整备份迁入 gnwmanager

这一阶段可独立推进；提交与验收范围与内核迁移分开。

迁移 `gnw_full_backup.py` 的行为：内部 Flash 双 bank、外部 Flash 全容量、双读比对、ITCM/选项字节/RTC 归档、大小与哈希 manifest、独立验证、选择区域恢复与读回校验，以及远程拉取/验证。

原始 RAM/ITCM 捕获须支持不复位、不先加载管理固件的低层读取，避免破坏现场。选项字节、RTC 等归档项的恢复权限和顺序按现有脚本实际能力保留，不能把“可归档”等同于“可无条件写回”。现有 gnwmanager unlock 核心流程继续保留。

增强维护中的 gnwmanager fork，并尽量向上游贡献。模拟器验证还不能证明实机兼容；退休 backup 前须覆盖现有实机备份/恢复路径、旧归档格式、损坏归档拒绝、读回不一致报错和远程拉取校验。

通过后移除 backup 子模块、运行依赖及脚本引用，保留历史备份文件和恢复说明，给 fork 留下最终 tag 后归档。此退出条件独立于工具链阶段三完成时间。

## 阶段三：当前会话接入与全功能验收

1. UI 发布本地会话入口。客户端可发现当前已加载设备，无须环境变量指定 ROM；没有活动会话时提示启动 UI 并加载 ROM。多会话时由用户明确选择，禁止任意选取一个目标。
2. 会话标识在进程重启或换 ROM 时变化。旧连接及时失效，操作绑定原会话，不自动转向新 ROM；入口清理和客户端错误须覆盖退出、崩溃及失效端点。
3. 补齐 GDBBackend 的目标寄存器识别、分包、错误处理、halt/resume/reset 时序与外部 GDB 连接交接。QEMU GDB stub 的单客户端限制须显式管理。
4. UI 继续持有 QMP 连接；gnwmanager 所需电源/输入等控制通过 UI 会话控制接口协调，避免假定 QMP 能接收第二个直接客户端。管理操作期间协调换 ROM、关闭、状态恢复和即时存档等冲突；操作中断时明确报告部分完成状态。
5. 以 gnwmanager 命令清单验收：备份/验证/恢复、刷写/擦除、格式化与文件管理、截图/监视、调试接管、解锁/重新保护、电源操作。RAM 管理固件所依赖外设、RDP/选项字节转换、冷启动及持久化均须实际测试。

gwemu 的 RDP 和冷启动实现可减少补课量，但不视为所有真实 STM32 行为已经验证。savestate 提供回滚，不能替代电池断开或保护转换。

## 后续计划与完成判定

该文档是三阶段路线和验收边界，不是一次性实施计划。各阶段开始时分别制定详细计划，确定接口细节、测试夹具与修改文件；原有功能迁移所需适配在阶段一解决，会话发现和管理控制协议在阶段三设计。

三个独立里程碑为：gwemu 接入通过现有功能回归；完整备份通过实机/模拟器适用路径与恢复验证；gnwmanager 工具链全流程通过验收。前两个里程碑分别允许退出对应旧 fork。
