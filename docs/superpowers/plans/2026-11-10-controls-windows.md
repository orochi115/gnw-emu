# Independent controls windows implementation plan

> For agentic workers: use subagent-driven-development for independent UI/main scopes and requesting-code-review. Test behavior with failing regressions before changes.

Goal: address approved user feedback: separate keyboard/gamepad and hotkey settings windows, preserve game geometry, simplify UI and fix screenshot defects.
Architecture: one main-owned native child BrowserWindow at a time; mode buttons/hotkeys selects fixed renderer page and native size. Existing main transaction/router remains authoritative across all windows. Dedicated settings renderer owns capture/polling; main game renderer keeps raw keyboard tracking but gamepads suspend while child exists. Shared settings unchanged; legacy default turbo resolved to explicit stored Hz in editor.

- [x] Native host: add main/control-window.ts to own window geometry/lifecycle, bounded sizes and centered placement. Main waits neutral QMP barrier before creating child, validates child-main-frame IPC explicitly, isolates until child destroyed, handles failed save/renderer loss/close while saving/reload. Keep main geometry and clock mode unchanged. Broadcast epoch/effective controls to both windows. Tests: window geometry and transaction cleanup.
- [x] Menu: Settings contains controls.open (buttons) and controls.hotkeys (hotkeys); remove controls from Edit. Keep native Edit text actions only. Tests verify placement, distinct actions and automation IDs.
- [x] Renderer: new ControlSettingsWindow entry selected by URL query, only controls-related trusted API available to child. Native OS titlebar, no WindowChrome or underlying game. Remove settings dialog from App; publish open state to disable game chassis and suspend gamepad polling. Dedicated settings keyboard listener tracks blocked presses/releases for quarantine and supplies capture UI.
