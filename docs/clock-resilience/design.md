# Desktop clock resilience

User authorizes implementation on master first, merge into special/windows-stock-dual, private Windows ZIP delivery, and cleanup of rebuilt temporary worktrees. Preserve unrelated working changes, previous ZIPs, UserData and firmware. No firmware BIN additions to Git.

Clock USB: clock mode requires USB power, including preference restore, native restart and snapshot load. During clock mode manual USB/battery controls cannot disconnect the required source. Leaving clock mode restores manual control; the current USB connection remains until changed by the user. This avoids an implicit power loss when leaving clock mode. Minimizing retains clock mode and USB.

Window: three compact top-left controls (return, minimize, close), proportional button size with total toolbar constrained to the clock width. Windows maintains topmost state without activating or moving/resizing the clock, on restore/session resume/shell reactivation and a low-frequency watchdog while visible. Stop watchers/timers on leaving clock mode/closing; skip minimized/hidden windows. Verify forced taskbar occlusion and recovery without dragging or stolen focus.

Recovery: bounded retry supervisor for startup native connection failures and runtime native/display crashes. Stop/await only the failed owned runtime, then load the same profile from its existing session; never manufacture successful saves, delete data or silently load quick snapshots. Preserve clock/USB/settings, log cause/old/new session IDs and retry count. Exponential delay, at most 3 retries per 5 minutes; cancellation on explicit stop/profile replacement/quit. Invalid profile, missing files, firmware mismatch and snapshot incompatibility are not retryable. Keep a visible terminal error after exhaustion; recovered sessions show a brief notice.

Lifecycle: own all spawned native processes, including capability probes. Windows Job Object with KILL_ON_JOB_CLOSE covers forced UI termination. Normal exit requests clean native shutdown, waits, then escalates only its owned processes. POSIX ownership must also terminate children when the desktop host dies. No process-name-wide kill. Native launch diagnostics retain bounded stderr, phase, exit/signal and timeout so connection failures no longer claim unsupported features without evidence.

Memory diagnostics: periodic low-volume structured records for main/renderer/utility/native memory, PID/session, handles and Windows system commit/limit. Bounded baselines/ring, rate-limited sustained-growth warnings; sample failures do not stop games. Do not call working-set fluctuations a confirmed leak or restart based only on a threshold. Normal frames/audio/IPC do allocate temporarily; the target is bounded retained memory, not zero allocations. Keep the 1 GiB default native JIT cache visible as a baseline rather than treating it as growth.

Acceptance: regression tests for USB invariant/snapshot/restart, recovery/cancellation/budget, native ownership and diagnostics; actual Windows forced crash and main termination, late taskbar occlusion recovery, three-button compact/minimize/restore, both stock EXEs under Chinese paths with relocation/save/load. Windows package built from pinned native and tested as extracted copies. Verify ZIP CRC/SHA256 and original firmware hashes; preserve old quick-snapshot compatibility warning.
